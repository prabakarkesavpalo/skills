# Build an app from the Gen-e2 project template

Outcome: a repo in the user's chosen folder that passes the template's own hooks, has every story's acceptance
scenario covered by a test, runs with `npm install && npm run dev`, and ships `docs/demo/sprint-1-demo.mp4`.
Worked example: **Makan Mate** (team hawker-lunch roulette) — see `references/makan-mate-example.md`.

Related skills: `gen-e2-template-conversion` (moving an *existing* repo onto the template),
`sprint-review-demo-video` (narrated 480p variant with `say`).

## 0. Before writing anything (10 min)

1. Unzip the template the user gave you into the scratchpad and **read**: `README.md`, `AGENTS.md`, `CLAUDE.md`,
   every `.github/instructions/*.md`, `.github/hooks/commit-msg`, `.markdownlint.json`, the example epic/story,
   `ADR-template.md`, `apps/design/DESIGN.md`. The rules there (MUST/SHOULD) are what the hooks and review skill check.
2. Confirm the Mac is linked (`get_device_info`) and request access to the **parent** folder of the target path once.
3. Check the container: `node -v` (22+), `ffmpeg`, Python Playwright (`python3 -c "import playwright"`), `markdownlint-cli2`.
4. Tell the user the product idea, stack and the four-ish stories in one message, then start — do not wait for approval
   unless the idea is risky. Pick something local and fun (Singapore flavour worked well) with a visible "wow" moment.

## 1. Product docs first, in the template's order

Fill, do not delete, the `_overview` set: `00-vision` (problem, vision sentence, G-0x goals, NFRs, out of scope),
`01-personas` (3 personas → each maps to a story), `02-user-roles`, `03-assumptions-and-constraints` (put the user's
constraints here, e.g. "JSON file as database"), `04-prioritization` (MoSCoW), `05-glossary` (names you will use in
code — the conventions rule says class/method names must match it), `99-product-decision-log`.

Then one epic folder `docs/requirements/epic-001-<name>/` with `overview.md`, `story-00N.md` (Given/When/Then table:
happy, unhappy, edge, persistence, accessibility) and `story-00N-plan.md` (phases 1–4 + commit strategy). Four stories is
the right size for one sprint: directory CRUD, the fun action, a write-back (rating/log), an aggregate (leaderboard/stats).
Delete the `epic-001-example` folder and `_overview/source/` transcripts.

## 2. Contract and decisions before code

- `docs/api/contracts/<app>-api.yaml` — OpenAPI 3.1, one tag per story, shared `ErrorResponse {code,message,details[]}`,
  stable codes (`VALIDATION_ERROR`, `NOT_FOUND`, `DUPLICATE_*`, domain ones like `NO_CANDIDATES`). Delete `example-api.yaml`.
- ADRs: ADR-002 stack, ADR-003 **JSON file database** (atomic temp+rename, single write queue, path via env var,
  seed file, exit criteria to SQLite), ADR-004 no auth (free-text first name). Fill the date in ADR-001.
- `docs/architecture/overview.md`: real C4 Mermaid, ADR table, "one door to the data" principle.
- `AGENTS.md` Stack section + a row for the stack rules file; create `.github/instructions/typescript.instructions.md`
  from the `.example`, then delete the `.example`; `CLAUDE.md` imports it; fill the commented rules in
  `backend`, `security`, `architecture` instruction files instead of leaving `<!-- -->` placeholders.
- `apps/design/DESIGN.md`: complete the YAML frontmatter (colours, type, radius, spacing) — the web `tokens.css`
  is generated by hand from it, nothing else may hardcode colours.

## 3. Code — npm workspace, TypeScript everywhere

```text
package.json            workspaces [services/api, apps/web]; dev = concurrently; test = both
services/api            Express 5 + zod + tsx; src/{domain,db,services,routes,middleware}; tests/ with supertest
apps/web                React 19 + Vite 6; src/{api/client.ts,components,features/<story>,styles/tokens.css}
```

Backend pattern (copy `references/json-store.ts`): routes parse with zod → services hold rules → `JsonStore` is the
only module importing `node:fs`. `createApp({dbPath, seedPath, random})` so tests get a temp file and a seeded RNG.
One `errorHandler` renders `AppError` and `ZodError` into the envelope; never leak stack traces.
Seed `data/seed.json` with 15–20 realistic rows plus history so the demo has data on first run; gitignore `db.json`.

Frontend: `api/client.ts` is the only `fetch`; `Field`, `Button`, `Dialog` (native `<dialog>`, never `window.confirm`),
`StarRating` (radio group), `Toast`; `aria-live` for the result; `prefers-reduced-motion` fallback for animation;
clear a field's error when the user edits it. Keep component files under 200 lines.

Tests: one `it("ACn: …")` per story scenario (supertest against a temp db, `restart()` helper for persistence AC),
unit tests for pure maths, a couple of jsdom component tests. Name tests after behaviour.

## 4. Quality gates (all must pass before the demo)

`npm test` · `npm run build` · `npx markdownlint-cli2 "**/*.md" "#**/node_modules"` · `npm audit --audit-level=high`
clean (security rule: no High/Critical — drop or upgrade the dep; markdownlint-cli2 stays out of `devDependencies`
and runs via `npx`) · Playwright screenshot of every tab, then **look** at the screenshots.

If an AC turns out to be mathematically wrong (Makan Mate: Bayesian prior = team average cannot guarantee the
fairness rule), fix the story/glossary/decision log **first**, then the code — and say so in the summary.

## 5. Sprint demo video

Reset the db (delete `db.json`, restart API), run `scripts/record-demo.py <url>` (adapt the scene list).
It injects a caption pill, full-screen title cards and a fake cursor, drives one story per scene, records 1280×800 webm,
converts with ffmpeg to h264 mp4 (~5 MB / 100 s), writes `docs/demo/sprint-1-demo.mp4`. Then extract 9 frames into a
contact sheet and check captions, dialogs and end cards. Add clean screenshots for the README (`docs/demo/*.png`).

## 6. Commit and deliver

- `git init -b main`, `./scripts/setup.sh` (installs hooks; extend it with Node check, `npm install`, `.claude/skills`
  symlink), then 4–5 conventional commits (`chore: 🔧`, `docs: 📚`, `feat(api): ✨`, `feat(web): ✨`, `docs(demo): 📚`).
  The `pre-commit` hook lints staged `.md`; `commit-msg` enforces the format.
- `tar --exclude=node_modules --exclude=dist --exclude=services/api/data/db.json -czf` → `device_commit_files` to the
  parent folder → `device_bash` `tar -xzf` → `npm install` and `npm test` **on the Mac** → `mv` the tarball to
  `_to_delete_*` (rm is blocked). Start the dev servers in the container with `setsid nohup … &`.
- Send the mp4 with `SendUserFile` as well; finish with features, template compliance, numbers, how to run, two notes.

## Gotchas collected on the first run

- `pkill -f vite` kills your own shell (the command line contains "vite") → exit 144. Use `pkill -f "tsx watch"`
  in a separate call, or match on something not in your command.
- `.claude/skills` symlink cannot be extracted into a connected folder (Claude-internal path is protected) — harmless,
  `setup.sh` recreates it; everything else extracts.
- Google Fonts are unreachable from the container, so recordings use fallback fonts; fine on the Mac.
- Playwright `role=tab[name*=…]` is not valid — use `button.tab:has-text('Stalls')` or `get_by_role(name=)`.
- `z.coerce.number()` for enum-ish query params (`priceBand=1`), and `safeParse` the `:id` into a 404, not a 400.
- markdownlint: MD024 needs `siblings_only` for persona-style repeated headings; MD038 trips on `` `$`, `$$` ``;
  MD013 is 400 chars — break long paragraphs; code fences need a language (`text`).
- Emoji medals render tiny in headless Chromium — bump font-size; they look right on macOS.
- Seed data must actually satisfy the demo's filter combo (first take had no Indian `$` stall → 404 mid-demo).
